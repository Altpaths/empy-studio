# Empy Studio

**یک لایه سبک برای هدایت Agentهای کدنویسی؛ از پروژه نیمه‌کاره تا Release کامل، کنترل‌شده و قابل بررسی.**

Empy Studio برای یک مسئله عملی ساخته شده است: وقتی پروژه‌ای ناقص را به یک Agent کدنویسی می‌دهیم، نباید مجبور شویم تاریخچه را بارها توضیح بدهیم، کل Repository را برای هر درخواست دوباره اسکن کنیم، هر مرحله کوچک را جداگانه تأیید کنیم یا خروجی چند Agent را دستی به هم بچسبانیم.

```text
پروژه + حافظه پایدار پروژه + درخواست
                    ↓
          برنامه اجرایی محدود
                    ↓
          اجرای Agentهای لازم
                    ↓
            آزمون و همگام‌سازی
                    ↓
             یک Release کامل
```

## مسئله‌ای که حل می‌کند

- کاهش مصرف توکن با Context محدود و هدفمند
- جلوگیری از Discovery و آپلود تکراری
- جلوگیری از تغییر فایل‌های نامرتبط
- مشخص‌کردن مالک هر فایل
- قفل‌کردن مسیر طراحی قبل از کدنویسی UI
- ثبت تفاوت میان تست اجراشده و تست محیط واقعی
- تحویل یک پروژه کامل به‌جای Patchهای پراکنده
- نگهداری تجربه معتبر برای پروژه‌های بعدی

## اجزای اصلی

- **Project Vault:** نسخه مرجع پروژه، تصمیم‌ها، نقشه و Releaseها
- **Orchestrator:** وظایف، وابستگی‌ها و موج‌های اجرا
- **File Ownership:** یک مالک نوشتن برای هر فایل در هر موج
- **Quality Gates:** کنترل طراحی، امنیت، QA و Release
- **Runtime Verification:** ثبت تست‌های موفق، ناموفق و وابسته به محیط
- **Learning:** ورود فقط الگوهای معتبر به دانش عمومی

## اصل مهم

Empy Studio نباید توسعه را پیچیده‌تر کند. هر قابلیت فقط زمانی وارد هسته می‌شود که مصرف توکن، دوباره‌کاری، ریسک یا اصطکاک تحویل را در چند پروژه کاهش دهد.

## شروع سریع

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install ".[dev]"
pytest
empy --help
```

## استفادهٔ مستقیم در مک، بدون ترمینال

از بستهٔ متناسب با معماری مک استفاده کنید: `empy-studio-macos-arm64.zip`
برای Apple Silicon و فایل x86_64 برای Intel. پس از Extract، برنامه را باز کنید.
نسخهٔ عادی پروژه‌ها، تیکت‌ها و نتایج را بین اجراها حفظ می‌کند. نسخهٔ آزمایشی
با فضای خالی، فقط با گزینهٔ ساخت `--clean-workspace` تولید می‌شود و از فضای
کاری عادی جداست. وضعیت امضا و تأیید اپل باید در گزارش همان بسته بررسی شود.

[راهنمای پنج هدف محصول](docs/five-goal-workflow.fa.md) حافظهٔ پروژه، تقسیم کار،
چرخهٔ اصلاح، شواهد مصرف و محل صحیح Extract در DirectAdmin را توضیح می‌دهد.

## وضعیت

**نسخه 0.1.51 — نامزد تکمیل محصول**

هستهٔ اجرایی آماده است و بسته‌های انتشار با manifest و checksum بررسی می‌شوند.

python scripts/build_release_assets.py --output build/release-assets
python scripts/verify_release_assets.py build/release-assets/release-assets.json

امضا و Notarization اپل همچنان Gateهای واقعی انتشار نهایی هستند و شبیه‌سازی
نمی‌شوند.
