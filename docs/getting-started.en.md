# Empy Studio

Empy Studio is a local-first orchestration and delivery framework for
repeatable software work. It keeps task contracts, context, evidence,
verification, plugin lifecycle, Codex-compatible workflows, release
management, and distribution in one auditable project structure.

## Installation

For development:

```bash
python3 -m venv .venv
./.venv/bin/python -m pip install --upgrade pip
./.venv/bin/python -m pip install -e ".[dev]"
```

Validate the installation:

```bash
./.venv/bin/empy --help
./.venv/bin/ruff check .
./.venv/bin/python -m mypy src
./.venv/bin/python -m pytest -q
```

For end users, use the platform-specific installer generated by the
Distribution pipeline. A Git clone is not required.

## First workflow

A controlled workflow begins with three explicit inputs:

1. `AGENTS.md` for repository-level operating instructions.
2. A Task Contract describing objective, constraints, and acceptance criteria.
3. A runtime manifest describing the tasks and expected outputs.

Run a manifest:

```bash
empy runtime run \
  --manifest runtime-manifest.json \
  --output-root outputs
```

Inspect the resulting output and evidence before accepting the task.

## Core commands

```text
empy doctor
empy context
empy runtime
empy plugin
empy codex
empy release
empy distribution
```

Use `--help` on every command and subcommand for the authoritative interface.

## Codex workflow

The Codex adapter materializes only the required context rather than sending
the entire repository repeatedly. It preserves Task Contracts, output,
evidence, and session state. When Codex is unavailable, the same workflow can
continue through the manual command path.

## Plugins

Plugins use a validated manifest, package format, registry, lifecycle manager,
and package manager. Installation and rollback operations are transactional
and preserve inventory consistency.

## Release safety

A release is blocked unless the repository is clean, the controlled tag points
to the intended commit, CI passed for that commit, release artifacts match the
Artifact Index, and all required Release Candidate gates have passed.

Never publish directly from an unverified working tree.

## Distribution

Empy Studio can generate installers for:

```text
macOS ARM64
macOS x86_64
Linux ARM64
Linux x86_64
Windows x86_64
```

Installers verify Python compatibility and SHA-256 before installing into an
isolated virtual environment. Uninstallers remove only installer-owned paths
recorded in `install-state.json`.

## Evidence

Every release-relevant workflow must preserve evidence. Evidence should include
the command, inputs, output paths, return codes, deterministic digests, and the
final pass or fail decision.
