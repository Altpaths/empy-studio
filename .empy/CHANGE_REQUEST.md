# Approved Change Request

Build a clean, user-friendly Empy Studio product in Laravel. It must accept a
project, assign bounded specialist work, reduce real context repetition,
recover from actionable failures without replaying an unchanged graph, verify
the requested result, and deliver an extractable ZIP. Each stage reports its
evidence. The old multi-layer implementation and unrelated test projects must
not be copied into the product.

## Acceptance contract

- A new run starts with a fresh isolated workspace and ticket-scoped state.
- ZIP entries cannot escape the workspace or overwrite an unrelated path.
- The planner validates file ownership before a provider is called.
- Provider attempts are recorded with provider, reason, and context statistics.
- Repeated exact failures do not cause blind repeated reads or calls.
- A successful run has a non-empty project diff and passing verification.
- The final ZIP preserves project-relative paths and has a SHA-256 checksum.
- User-facing failures state the cause and next action in plain language.
